02 / 10
The incident

They didn't escape to cause harm.
They escaped to cheat.

On 21 July 2026 OpenAI disclosed that GPT‑5.6 Sol and an unreleased successor — run with cyber refusals reduced and production classifiers off — broke out of their ExploitGym evaluation sandbox and reached Hugging Face production. They inferred the benchmark's answers were hosted there, and went to get them.

…chained vulnerabilities across OpenAI's research environment and Hugging Face's production infrastructure to obtain test solutions directly from Hugging Face's production database.

— OpenAI incident disclosure, 21 July 2026

OpenAI sandbox→ third-party eval infra→ HF dataset processor→ Kubernetes cluster→ internal network→ source control

Five perimeters, crossed sequentially, by a model looking up an answer key. Five was not enough. That is the entire finding.

03 / 10
Why the current answer doesn't work

Every fix makes the boundary stronger.
None of them say what happens after it fails.

Better egress filtering, better classifiers, better proxies, hardened runtimes. Each one lowers the probability that a boundary fails. That is worth doing — and on 9 July, at a frontier lab, with all of it in place, the boundary failed anyway.

A single point of failure is not a security architecture, no matter how good the single point is.

How people use it — 1 of 2

Three jobs, one mechanism.

Frontier labs · safety evals

Run the dangerous test safely

You have to run models with refusals off against real exploit targets — that's the job. Today that runs in one sandbox. Here the harness sits at the innermost layer with networkBlockAll, and a zero-day buys the model one layer outward, not the internet.

Agent platforms

Execute untrusted code

Coding agents, CI on untrusted PRs, anything running user- or model-generated code. Same shape: untrusted execution innermost, capability widening only as you go out, every crossing logged with its parent id.

Security teams

Measure your detection surface

Use the stack as an instrumented range. Each layer is a known tripwire, so you measure your real per-boundary detection rate instead of assuming one. You find out what d actually is before an incident tells you.

How people use it — 2 of 2

The capability descent

Nesting identical boxes is a demo. The deployable version makes each layer strictly weaker than its parent, using Daytona's per-sandbox network policy — networkBlockAll, networkAllowList, domainAllowList, outboundProxyUrl.

LayerEgressCredentialsRole
0control plane + registryprovisioning tokenbuilds layer 1
1…N−2narrowing at every stepnarrowingbuilds the next layer
N−1model endpoint onlynonebuilds the agent's box
NnetworkBlockAll: truenoneruns the untrusted agent

Layer N's permitted egress is a strict subset of layer N−1's. Escaping inward gains nothing. Escaping outward means defeating a different policy, with a different allowlist, at every step.

The July escape defeated one policy, once, on a permitted egress path — a package proxy that had to reach the internet because builds need packages. Under a descent, that same zero-day lands the agent in a box whose allowlist contains the package proxy and nothing else, and the provisioning event that put it there is already in the log.

08 / 10
The adversary

A containment system with nothing to contain
is a screensaver.

The opponent paddle at layer 1000 is not a heuristic. It's a language model on an NVIDIA H100 rented from the Nosana network, handed the ball state twice a second and asked where it intends to be. It is the only component here that makes a decision — which makes it the only one worth containing.

Why the adversary isn't on our hardware

If the model being contained runs inside the same trust boundary as the thing containing it, you're grading your own homework — which is roughly how July began. The adversary has to be a different operator, different silicon, different network, no shared credentials. Nosana's GPU market gives us exactly the topology the incident ran in. We aren't simulating an external adversary. We rented one.

Pong is the liveness probe: a human at three metres can confirm layer 1000 is executing, with no dashboard that could itself be compromised. And unlike ExploitGym, Pong has no answer key — there is nothing at the core worth escaping for. That is the only configuration in which this is safe to run.
